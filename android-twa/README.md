# Android-приложение «Ай, настойка!» (TWA)

Это обёртка Trusted Web Activity: приложение открывает сайт **ai-nastoika.ru**
на весь экран без адресной строки браузера. Внутри — тот же сайт, поэтому любое
изменение на сайте автоматически появляется в приложении. Отдельный код
поддерживать не нужно.

Собирается **отдельно** от сайта, на вашей Windows-машине. Ниже — все шаги
по порядку. Команды выполняются из папки `android-twa`, если не сказано иное.

---

## Что нужно установить один раз

1. **JDK 17** — https://adoptium.net (Temurin 17). После установки проверьте:
   ```powershell
   java -version
   ```
   Должно показать версию 17.

2. **Android SDK** — проще всего поставить **Android Studio**
   (https://developer.android.com/studio). При первом запуске он сам скачает SDK.
   Либо только command-line tools, если не нужен редактор.

3. Прописать переменную окружения `ANDROID_HOME` на папку SDK
   (обычно `C:\Users\ВЫ\AppData\Local\Android\Sdk`). В Android Studio путь виден
   в *Settings → Languages & Frameworks → Android SDK*.

---

## Шаг 1. Создать ключ подписи (один раз, навсегда)

⚠️ **Этот ключ нельзя терять и нельзя менять после публикации.** Потеря =
невозможность выпускать обновления. Храните файл ключа и пароли в надёжном месте
(и резервную копию).

Из папки `android-twa` выполните (JDK кладёт `keytool` в свой `bin`):

```powershell
keytool -genkeypair -v -keystore ai-nastoika.keystore -alias ai-nastoika -keyalg RSA -keysize 2048 -validity 10000
```

Ответьте на вопросы (имя, организация и т.п. — можно свои данные), задайте и
запомните **пароль хранилища** и **пароль ключа**.

Затем скопируйте шаблон и впишите туда свои пароли:

```powershell
copy keystore.properties.example keystore.properties
notepad keystore.properties
```

`keystore.properties` и сам `.keystore` в git не попадут (см. `.gitignore`) — это
правильно, секреты не должны лежать в репозитории.

---

## Шаг 2. Узнать отпечаток ключа (SHA-256) и вписать в сайт

```powershell
keytool -list -v -keystore ai-nastoika.keystore -alias ai-nastoika
```

Найдите строку `SHA256:` — это длинная последовательность байтов через двоеточие,
например `AB:CD:12:...`. Скопируйте её целиком.

Откройте в основном проекте сайта файл
`public/.well-known/assetlinks.json` и замените плейсхолдер
`ЗАМЕНИТЬ_НА_ОТПЕЧАТОК_КЛЮЧА_ПОДПИСИ` на этот отпечаток. Закоммитьте и
задеплойте сайт — файл должен стать доступен по адресу
`https://ai-nastoika.ru/.well-known/assetlinks.json`.

> **Про Play App Signing.** Когда вы загрузите приложение в Google Play, Google
> по умолчанию подписывает его **своим** ключом (Play App Signing). Тогда в
> `assetlinks.json` нужен отпечаток **из Play Console** (раздел
> *Setup → App integrity → App signing*, там будет свой SHA-256), а не только
> ваш локальный. Можно указать оба отпечатка в массиве
> `sha256_cert_fingerprints` — это нормально и рекомендуется. Пока приложение не
> загружено, впишите локальный; после первой загрузки добавьте отпечаток от Google.

## Шаг 3. Собрать .aab (файл для загрузки в Google Play)

```powershell
.\gradlew.bat bundleRelease
```

Готовый файл появится здесь:
```
app\build\outputs\bundle\release\app-release.aab
```

Для быстрой проверки на своём телефоне удобнее APK:
```powershell
.\gradlew.bat assembleRelease
```
→ `app\build\outputs\apk\release\app-release.apk` — его можно перекинуть на
телефон и установить вручную (нужно разрешить установку из неизвестных
источников).

---

## Шаг 4. Проверить, что связь с сайтом работает

Установите APK на телефон и откройте приложение. Признак успеха: сайт открывается
**без адресной строки браузера** сверху. Если строка есть — значит
`assetlinks.json` на сайте ещё не совпал с ключом (проверьте Шаг 2, дождитесь
деплоя сайта, переустановите приложение).

---

## Шаг 5. Публикация в Google Play (когда будете готовы)

1. Завести аккаунт разработчика: https://play.google.com/console (разовый взнос $25).
2. Создать приложение, заполнить карточку (описание, скриншоты, иконка 512×512,
   фичер-графика 1024×500, политика конфиденциальности — у вас уже есть страница
   `/privacy`).
3. Загрузить `app-release.aab` в трек (внутреннее тестирование → потом продакшн).
4. После первой загрузки — добавить SHA-256 от Google Play в `assetlinks.json`
   (см. примечание в Шаге 2).

---

## Как выпускать обновления приложения

Само содержимое (сайт) обновляется автоматически — приложение всегда показывает
актуальную версию сайта, пересобирать ради этого ничего не нужно.

Пересборка `.aab` нужна только если меняется сам контейнер (иконка, название,
splash, версия Android). Тогда:
1. Поднимите `versionCode` (на +1) и `versionName` в `app/build.gradle`.
2. Снова `.\gradlew.bat bundleRelease`.
3. Загрузите новый `.aab` в Play Console.
